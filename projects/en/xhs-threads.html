xhs-threads

You only save; the AI does the organizing.

Bookmarking is frequent; organizing almost never happens, and the thought you had at the moment of saving has nowhere to live. I turned organizing into zero-label, proactive archiving: the system runs automatically on a schedule, and the AI decides which thread each new bookmark belongs to, writes a note and checks it automatically, while the threads keep branching and growing as bookmarks come in. What the product builds up is not content summaries but the user’s own trail of thought.

Problem

The bookmarks keep coming; the thoughts get lost.

Every time you tap save, there is a thought in that moment: my project could use this method; this post contradicts the one I read last week. But that thought has nowhere to go. The bookmark folder stores only the content, and when you look back a few months later, it is a pile of links you cannot remember why you saved.

  • Saving takes a few seconds and happens every day; organizing means sitting down specifically to do it, so it basically never happens.
  • Expecting users to build an organizing habit pushes the problem the product should solve back onto the user. The right question is: can organizing need no user involvement at all?
  • What is valuable is “why you saved it at the time,” not content categories. Once that is lost, you cannot get it back.
Differentiation

Competitors wait for the user to start; I let the system act on its own.

A survey of four competitor types confirmed that existing tools all treat bookmark organizing as content categorization, and most need the user to start it. With community tools you export and then organize yourself; AI tools also categorize only once each time the user makes a request. I found no approach that was zero-label and grew automatically with the bookmarks. The differentiation was set on this basis and written up as 8 product judgments that constrain every later feature trade-off.

Evaluation

What the AI writes for users has to pass a quality check first.

Text the AI produces goes straight into the user interface, in volume, and cannot be checked by hand item by item. So I built automated review: a reviewer model independent of the generation model scores against written criteria, the same item is reviewed three times and the majority decides, and a failing item is sent back for a rewrite. If the rewrite still fails, it goes to a human; nothing is silently let through.

Pre-launch acceptance

7 bad samples, all caught.

Before launch I deliberately built 7 typical bad samples (fabrication, empty talk, wrong thread) as the acceptance set, and only let it go live after the review caught every one of them.

Key mechanism

The reviewer model must be independent.

Letting a model grade itself is the same as not grading. Review runs on a different model, three reviews take the majority, and the criteria are written into a document rather than improvised.

Evaluation literacy

I even measured the error of the ruler itself.

Threading accuracy in a single measurement was 30/36 (83%), against only 31% for the strongest trivial baseline. Rerunning the same criteria four times gave 30/28/28/31: a noise floor of ±3. Any “improvement” smaller than the noise does not count. No telling stories about noise.

Unit Economics

15 calls per note, 90% on the light tier.

From deciding where it belongs to being fully written, one note goes through 15 model calls on average (measured from the ledger: 622 calls, 41 notes). All-flagship costs too much and all-light gives unstable quality, so calls are routed to a tier by task: classification judgments go to the light tier, writing goes to the flagship tier.

  • Every call is logged. Purpose, tier and token usage are all recorded, and the cost report can be reproduced with one command.
  • Measured structure. About 90% of calls land on the light tier. The model cost per item is currently about 0.05–0.10 yuan. Early ledger entries had evaluation calls mixed in; after I fixed the bookkeeping (each step’s call now carries a note tag), I am re-measuring the exact figure, rather than giving a number first that I know is inaccurate.
  • A quality backstop. Output that fails review is rewritten automatically, and if that still fails, it goes to a human. Saving money cannot come from quietly lowering quality.
