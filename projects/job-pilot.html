Problem

求职的卡点不在信息，在人。

我自己求职时发现，真正卡住我的不是岗位信息不够：

  • 筛出了 37 个高分岗，定制了 19 份简历，一个都没投出去。
  • AI 生成的打招呼话术，我每次都要改，因为它不像我说话。
  • 两个 offer 摆在面前，不知道按什么标准选。

海投工具和模板工具解决不了这些。它们停在行为层，只看你做了什么，不管你为什么这么做。

「它对我 0 投递的诊断不是『加油快投』，是『你在乎的事用了过高的标准，先允许自己投一个不完美的版本』。这种话，关键词匹配说不出来。」

— 军师给我的第一个真正有用的诊断
Insight

从行为层挪到认知层。

这是它和市面工具的根本区别，也是整个项目唯一想证明的事：

维度行为层工具（市面主流）JobPilot
建模什么
你怎么做：投递、点击、偏好
你怎么想（决策方式、盲区、价值排序）加上你怎么说（语言风格）
给你什么
更多岗位、通用话术
针对你的诊断、像你写的话术、扛得住追问的建议
最锋利处
「推荐你投这 50 个岗」
抓到「你说的」和「你做的」之间的矛盾

声明和推断分得很清楚：你声明的偏好（城市、deal-breaker）是硬规则，军师必须守；推断出来的认知是理解层，帮它调整说话方式、看出你卡在哪。两边打架的地方，往往就是最值钱的洞察。

Decisions

四个取舍，每个都想清楚了为什么。

  • 不做自动投递，不写爬虫。投递不可逆，平台也有反爬边界。定位是「我们生成、你来发」，用克制换信任。
  • 计划和跟进用规则算，不烧 LLM。「本周该投哪几个」能算就不调 API。省钱，而且每条建议都指得回数据，扛得住「凭什么」。
  • 两段式打分。免费的启发式先把全部岗位粗筛一遍，只对 top N 调 API 精评，一次跑完成本可控。
  • 简历定制是往原 docx 打补丁，不重新生成。用 difflib 把改动补回原文件，保留字体与排版；技能白名单防止 AI 写入我并不具备的能力。

工程底线流水线各阶段互相隔离，一个渠道挂了不影响其他；没有 API key 时降级到启发式，基本功能不瘫。pipeline-all 一条命令跑完全流程。

Honest Limits

跑通了，也想清楚了下一步难在哪。

真正的难题

不是多用户，是冷启动。

数据层早就按用户隔离了，多用户在工程上不难。难的是：一个陌生用户怎么快速获得这种深度的理解。现在最强的个性化恰恰来自只深度绑定我一个人，过早通用化就稀释成普通工具了。

我的打算

渐进式深度。

新用户只填 5 分钟问卷，给几段自己写的话术，然后越用越懂：每次对话攒认知信号，每次改话术系统更像你。不追求一上来就准，追求像一个跟了你三个月的人。

「这个项目想证明的不是我会写多少功能，是每个决策我都想清楚了为什么。」
